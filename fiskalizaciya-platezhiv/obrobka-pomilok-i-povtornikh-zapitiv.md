# Обробка помилок і повторних запитів

Якщо перевірка операції не пройшла, відповідь може мати статус `FAIL` і поля `errorCode` та `errorDescription`. Наприклад, у прикладі відповіді API для акцизного товару без УКТЗЕД повертається код `b_bucket_excise_product_without_classification_code_error`.

Перед повторним надсиланням запиту після технічної помилки перевірте його результат і врахуйте правила повторної обробки, щоб уникнути дублювання фіскальних чеків.

> **Потрібно доповнити:** Повний перелік помилок і правила безпечного повторного надсилання запитів наразі не описані.
