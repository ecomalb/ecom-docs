## Процес Completion для режиму PREAUTH <a href="#proces-completion-dlya-rezhimu-preauth" id="proces-completion-dlya-rezhimu-preauth"></a>

У режимі `PREAUTH` під час першого етапу платежу банк лише авторизує операцію та тимчасово блокує кошти на картці клієнта. Щоб завершити платіж і фактично списати кошти, необхідно виконати окрему операцію `Completion`.

**Послідовність виконання**

1. Покупець завершує оплату через HPP, а модуль отримує успішний результат операції `PREAUTH`.
2. Замовлення переводиться у статус, налаштований у полі **PreAuth order state** (наприклад, _Очікується оплата банківським переказом_).
3. Після підтвердження замовлення або готовності товару адміністратор переводить його у статус, налаштований у полі **Completion trigger order state** (наприклад, _Оплату прийнято_).
4. Модуль використовує збережені дані авторизованої операції та надсилає до API запит `Completion` на списання коштів.
5. Після успішної відповіді API замовлення залишається або переводиться у статус **Оплату прийнято**. Клієнту можна відправити підтвердження оплати та розпочати обробку замовлення.

**Важливі умови**

* Операцію `Completion` потрібно виконати до завершення періоду, заданого в **PreAuth expiration period** (у прикладі — `2h`).
* Не слід виконувати `Completion` повторно для вже завершеної операції: повторний запит може бути відхилений банком.
* Якщо авторизація прострочена, скасована або запит `Completion` завершився помилкою, кошти не списуються. Перевірте відповідь API та налаштування статусу помилки.
* Суму до списання та ідентифікатор початкової авторизації необхідно брати із замовлення й даних платежу, збережених модулем; не вводьте їх вручну без перевірки.

{% hint style="warning" %}
**Увага:** переведення замовлення у статус _Completion trigger order state_ запускає завершення PREAUTH лише якщо така автоматизація реалізована та увімкнена у поточній версії модуля. Перед використанням у production перевірте сценарій у тестовому середовищі.
{% endhint %}
