# Усунення проблем (FAQ)

Перед перевіркою переконайтеся, що використовуєте актуальну версію плагіна та параметри підключення, погоджені з банком. Налаштування описано на сторінці [«Налаштування та авторизація»](https://docs.merchant.alb.ua/platizhni-vidzheti-dlya-cms/wordpress/nalashtuvannya-ta-avtorizaciya).

### Запит відхиляється через підпис або параметри авторизації

* Перевірте Base URL і Merchant ID: вони мають відповідати одному середовищу.
* У JWS Private Key має бути повний приватний RSA-ключ у форматі PKCS#8 PEM разом із рядками BEGIN PRIVATE KEY та END PRIVATE KEY. Не додавайте до нього лапки чи інший текст.
* Переконайтеся, що JWS Key ID (kid) належить відкритому ключу, зареєстрованому в банку, і відповідає цьому приватному ключу.
* Перевірте синхронізацію системного часу сервера: підпис містить часову мітку ts.
* Перевірте доступність API банку із сервера магазину та потрібні PHP-розширення.

Плагін формує JWS для кожного запиту автоматично. Параметри підпису не потрібно додавати вручну в замовлення.

### Покупець повернувся після оплати, але статус не оновився

1. Відкрийте замовлення та натисніть **Статус платежу**. Перевірте результат конкретної операції й примітки.
2. Перевірте доступність callback-маршруту `/wp-json/alb/v1/notify` через HTTPS. Авторизація сайту, firewall або захист REST API не повинні блокувати повідомлення банку.
3. Перевірте, чи отримано callback і чи успішно перевірено його JWS-підпис. Серверу потрібен доступ до відкритих ключів банку.

Не визначайте результат оплати лише за Success URL. За відсутності callback сторінка статусу може отримати дані прямим запитом до банку, але причину недоставлених повідомлень потрібно усунути.

### AlliancePay не відображається під час оформлення замовлення

Перевірте активацію плагіна, WooCommerce та ввімкнення AlliancePay у **WooCommerce → Налаштування → Платежі**. Для класичного оформлення використовуйте сторінку з `[woocommerce_checkout]`. Для описаного сценарію підписок використовуйте саме класичну сторінку; наявність підтримки звичайної оплати у Checkout Blocks не підтверджує сумісність усіх сценаріїв підписки.

### Не вдається виконати COMPLETION

Перевірте, що платіж створений як PREAUTH, кошти зарезервовано, строк резервування не завершився і callback містить operation\_id. Перехід замовлення має відбутися саме у налаштований **Completion Trigger Status**. Перевірте суму замовлення та повідомлення про помилку в примітках. У v1.8.0 модуль перевіряє відхилення суми в межах ±20% початкової авторизації.

### Повернення не виконалося або ще має статус PENDING

Перевірте вихідну успішну операцію PURCHASE/COMPLETION, суму повернення та попередні повернення. Для A2A цей механізм не підтримується. PENDING означає, що остаточний результат ще потрібно перевірити. Не надсилайте повторне повернення, доки не з’ясовано результат попереднього запиту.

### Покупець не може оформити підписку

Перевірте вхід покупця в обліковий запис, прапорець **Enable subscription purchase** у товарі, прив’язку активного плану та його синхронізацію з банком. Покупець має вибрати **Subscribe** і конкретний план. Підписка оформлюється окремо від інших товарів у кошику.

### Підписка має PENDING після успішної першої оплати

У v1.8.0 локальний статус підписки може залишатися PENDING, коли замовлення WooCommerce вже має статус **Active Subscription**. Це різні статуси. Перевірте SUCCESS конкретної платіжної операції, отриманий callback і примітки замовлення; не використовуйте лише PENDING для висновку про неоплату.

### Не відображаються заплановані платежі або недоступна Run Now

Перевірте обробку callback першого оформлення та наявність ідентифікаторів запланованих платежів. Run Now доступна для WAITING, RETRY і FAIL\_WITHOUT\_RETRY за наявності scheduledPaymentId. Кнопка запускає реальний платіж; її не слід використовувати для простого оновлення інформації.

### Нова ціна не застосувалася до чинних підписників

**Replace with new price for new customers** створює план для нових оформлень. Для чинних підписників використовується окрема дія **Reprice for all current subscribers**: повний набір правил, дата щонайменше через 30 днів і підтвердження повідомлення покупців до набрання змінами чинності. Зміна звичайної ціни товару WooCommerce не змінює правила плану.

### Скасування підписки не повернуло попередні платежі

Скасування та повернення — окремі операції. Після **Cancel Subscription** перевірте CANCELED і стан замовлення. Для повернення вже сплачених коштів оформіть окреме повернення.

### Які дані передати для діагностики

Укажіть версії WordPress, WooCommerce і плагіна, час події, номер замовлення, ідентифікатор запиту або операції та текст помилки. Для підписок додайте planId, HPP order ID і scheduledPaymentId, якщо вони є. Не додавайте приватні ключі, повні платіжні реквізити чи зайві персональні дані покупця.
