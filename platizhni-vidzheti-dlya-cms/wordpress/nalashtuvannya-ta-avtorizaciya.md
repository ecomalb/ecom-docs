# Налаштування та авторизація

Модуль AlliancePay для WordPress + WooCommerce використовує [Авторизацію 2.0](https://docs.merchant.alb.ua/avtorizaciya-2.0): кожен запит до API підписується приватним ключем мерчанта у форматі JWS. Інструкція відповідає плагіну [v1.8.0](https://github.com/alliancedigital-tech/alliancepay-woocommerce/releases/tag/v1.8.0).

### Підготовка до підключення

1. Узгодьте з банком середовище API, Merchant ID і доступні типи платежів.
2. Підготуйте пару RSA-ключів для підпису RS256. Зареєструйте відкритий ключ у банку за інструкціями розділу «Авторизація 2.0» та отримайте його ідентифікатор `kid`.
3. Приватний ключ збережіть на стороні мерчанта. До банку передається відкритий ключ; приватний ключ не надсилайте та не публікуйте.
4. Переконайтеся, що сайт доступний через HTTPS, а сервер може надсилати запити до API банку та приймати callback.

### Налаштування модуля

Відкрийте **AlliancePay → Settings (Налаштування)**, заповніть наведені нижче параметри й натисніть **Save Changes (Зберегти зміни)**.

| Поле             | Що вказати                                                                                                                                                 | Обов’язковість             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| Base URL API     | Адреса API узгодженого середовища. Для робочого середовища: `https://api-ecom-prod.bankalliance.ua`.                                                       | Так                        |
| Merchant ID      | Ідентифікатор мерчанта, наданий банком для відповідного середовища й типу платежу.                                                                         | Так                        |
| JWS Private Key  | Повний приватний RSA-ключ у форматі PEM (PKCS#8), разом із рядками `-----BEGIN PRIVATE KEY-----` та `-----END PRIVATE KEY-----`. Алгоритм підпису — RS256. | Так                        |
| JWS Key ID (kid) | Ідентифікатор зареєстрованого відкритого ключа, що відповідає приватному ключу в JWS Private Key.                                                          | Так                        |
| HPP Payment Type | Тип одноразового платежу: PURCHASE, A2A або PREAUTH.                                                                                                       | Так                        |
| Success URL      | Сторінка магазину, на яку повертається покупець після успішного сценарію на HPP. Приклад: `https://shop.example.com/payment-success/`.                     | За налаштуваннями магазину |
| Fail URL         | Сторінка магазину для повернення після неуспішного сценарію. Приклад: `https://shop.example.com/payment-failed/`.                                          | За налаштуваннями магазину |

Плагін автоматично формує JWS-підпис із параметрами `alg`, `kid`, `ts`, `targetUrl` і `jti`. Час сервера має бути синхронізований. Для коректного відображення дат налаштуйте часовий пояс сайту в **Налаштування → Загальні**.

### Типи платежів

| Значення | Призначення                                                                                 |
| -------- | ------------------------------------------------------------------------------------------- |
| PURCHASE | Оплата з переходом покупця на платіжну сторінку банку.                                      |
| A2A      | Переказ між рахунками. Тип платежу та відповідний Merchant ID мають бути підключені банком. |
| PREAUTH  | Резервування коштів із подальшим підтвердженням списання через COMPLETION.                  |

#### Параметри PREAUTH

| Поле                                                        | Призначення                                                                                                  |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| PREAUTH: Pre-Auth Expiration                                | Строк резервування коштів: від 2 годин до 28 днів. COMPLETION потрібно виконати до його завершення.          |
| PREAUTH: On-Hold Status (after preauth creation)            | Статус замовлення після PREAUTH. Типове значення — On hold (На утриманні).                                   |
| PREAUTH: Completion Trigger Status (admin confirms capture) | Перехід замовлення в цей статус запускає запит на списання коштів. Типове значення — Processing (В обробці). |

Порядок підтвердження платежу описано на сторінці [«Функціонал»](https://docs.merchant.alb.ua/platizhni-vidzheti-dlya-cms/wordpress/funkcional).

### Callback — повідомлення про результат

Стандартна адреса отримання повідомлень: `https://shop.example.com/wp-json/alb/v1/notify`. Замініть домен на адресу свого магазину. Модуль передає цю адресу в `notificationUrl` платіжних запитів.

Забезпечте доступність цього маршруту для банку. Плагін перевіряє JWS-підпис callback за відкритим ключем банку й лише після успішної перевірки обробляє результат. Ключ банку отримується автоматично за `kid` повідомлення.

**Повернення покупця на Success URL саме по собі не підтверджує оплату.** Перевіряйте результат у статусі платежу та отриманому callback.

### Перевірка підключення

1. Увімкніть AlliancePay у **WooCommerce → Налаштування → Платежі**. Там само можна задати назву й опис способу оплати.
2. У погодженому тестовому середовищі оформіть замовлення та завершіть оплату на HPP.
3. Відкрийте замовлення й перевірте результат через **Статус платежу**, отримання callback і примітки замовлення.
4. Якщо результат не оновився, скористайтеся розділом [«Усунення проблем (FAQ)»](https://docs.merchant.alb.ua/platizhni-vidzheti-dlya-cms/wordpress/usunennya-problem-faq).
